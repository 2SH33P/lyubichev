# 柳比歇夫时间账本 · Lyubishchev Time Ledger

一个纯前端、离线优先的 PWA，用来践行 **柳比歇夫时间记录法**：如实记录每一段时间的去向，按“第一类 / 第二类 / 生活”分类统计，定期复盘。
部署在 GitHub Pages，数据保存在浏览器本地（IndexedDB），可选通过 **腾讯云 COS**（或任意 S3 兼容存储）在多设备间同步。界面采用 iOS 26 Liquid Glass 风格，适配手机、平板与桌面，支持中文 / English、浅色 / 深色。

## 功能

| 模块 | 说明 |
| --- | --- |
| 今日 | 一键计时（切换分类自动结束上一段）、暂停/继续、备注；24h 时间线、未记录空档提示与一键补记；当日汇总与今日待办 |
| 待办 | 快速添加、优先级、截止日期、预估用时、子任务、标签；从待办直接开始计时，自动累计实际用时 |
| 记录 | 按时间段/分类/关键词筛选，批量删除（自动先做快照），CSV 导出 |
| 统计 | 日/周/月/年；总时长、工作时间、第一类占比、环比；按天堆叠趋势、分类/类型分布、分类树明细、计划完成度、每小时产出、待办预估准确度、标签、年度热力图；导出 Markdown 报告 |
| 计划 | 为周/月/年设置各分类的小时目标，可复制上期 |
| 复盘 | 自动统计本期 vs 上期，书写小结（自动保存）；锁定后保存统计快照，本期记录只读 |
| 分类 | 多级分类树，类型（第一类/第二类/生活）、颜色、是否计入工作、默认产出单位、归档 |
| 版本 | 每日自动快照、导入/恢复/批量删除/加密变更前自动快照、手动快照；单条记录修改历史；云端完整备份 |
| 导入导出 | JSON 完整备份（可加密）、合并或覆盖导入（带预览）；CSV 导入（自动识别中英文表头、列映射、去重）与导出 |
| 同步 | 腾讯云 COS / S3 兼容；默认端到端加密（可关闭）；增量同步 + 自动压缩；冲突按记录级合并，旧版本进入修改历史 |

设置中可调整：时间重叠（默认禁止，可允许）、结束时间取整、最短记录、空档提示阈值与时段、每周起始日、语言、外观、降低透明度。

> 按需求，本应用 **不包含通知/提醒功能**。

## 柳比歇夫方法怎么用

1. **分类**：把时间分为“第一类”（核心创造性工作，如写作、研究）、“第二类”（辅助性工作，如会议、邮件、杂务）和“生活”。默认已建好一套分类，可在“分类”页调整。
2. **随手计时**：开始做一件事就点对应分类；换事情时直接点下一个分类，上一段会自动结束。忘记计时可在时间线上点“未记录”空档补记。
3. **记录产出**：在记录里填写产出数量与单位（页、字、题……），统计页会算出“每小时产出”。
4. **计划与复盘**：每月（或每周）设定各类时间目标；周期结束时在“复盘”页对比本期与上期，写下小结并锁定。

## 部署到 GitHub Pages

1. 新建 GitHub 仓库并推送本项目到 `main` 分支。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送后 `.github/workflows/deploy.yml` 会自动：安装依赖 → 运行测试 → 构建 → 发布。
   - 访问路径会根据仓库名自动设置：仓库名为 `<user>.github.io` 时为 `/`，否则为 `/<仓库名>/`。
4. 打开 `https://<user>.github.io/<仓库名>/`，在手机浏览器中“添加到主屏幕”即可像原生 App 一样使用（iOS 需用 Safari）。

应用使用 hash 路由（`#/today`），无需任何服务器端重写规则。新版本发布后，应用内会提示“新版本已就绪”，点击更新即可。

## 配置腾讯云 COS 同步

应用内“设置 → 多端同步 → COS 配置指南”会根据你填写的信息生成可直接复制的规则。步骤如下：

1. **创建存储桶**：COS 控制台创建存储桶，访问权限选 **私有读写**。记下名称（形如 `mybucket-1250000000`）和地域（如 `ap-guangzhou`）。
2. **配置跨域（CORS）**：存储桶 → 安全管理 → 跨域访问 CORS 设置，添加规则：
   - 来源 Origin：`https://<user>.github.io`（本地开发可再加 `http://localhost:5173`）
   - 操作 Methods：`GET, PUT, HEAD, DELETE`
   - Allow-Headers：`*`
   - Expose-Headers：`ETag, x-cos-request-id`
   - 超时 Max-Age：`600`
3. **创建子账号密钥（强烈建议）**：访问管理 CAM → 新建子用户（仅编程访问），授予只限该存储桶/前缀的策略：

   ```json
   {
     "version": "2.0",
     "statement": [{
       "effect": "allow",
       "action": ["name/cos:GetObject", "name/cos:PutObject", "name/cos:DeleteObject", "name/cos:HeadObject", "name/cos:GetBucket"],
       "resource": [
         "qcs::cos:<region>:uid/<APPID>:<bucket-APPID>/lyubishchev/*",
         "qcs::cos:<region>:uid/<APPID>:<bucket-APPID>/"
       ]
     }]
   }
   ```

4. 在应用中填写存储桶、地域、SecretId、SecretKey（路径前缀默认 `lyubishchev`），点“测试连接”，设置同步密码后“启用同步”。
5. 其他设备：填写相同的存储桶与密钥，测试连接会提示“发现已有同步数据”，输入同一个同步密码即可加入。

其他 S3 兼容服务（如 Cloudflare R2、MinIO、AWS S3）选择“S3 兼容”，填写 Endpoint 与地域即可，同样需要配置 CORS。

### 安全说明

- 本应用没有后端服务器；密钥只保存在当前浏览器的 IndexedDB 中，请只在自己的设备上使用，并使用最小权限的子账号密钥。
- 端到端加密默认开启：数据在本地用 PBKDF2（SHA-256，31 万次迭代）派生的 AES-256-GCM 密钥加密后再上传，云端只能看到密文。
- **同步密码无法找回**。忘记密码后云端数据无法解密（本地数据不受影响，可“断开同步”后用新密码重新创建同步空间）。
- 可随时在同步设置中开启/关闭加密或修改密码，会自动重写云端数据，其他设备需重新输入密码。

## 同步与版本设计

- 每条记录带有 **混合逻辑时钟（HLC）**；合并采用记录级“最后写入胜出”，被覆盖的一方会保存进该记录的修改历史，可随时恢复。删除为软删除（墓碑），保证多端一致。
- 云端目录结构（位于前缀下）：
  - `meta.json`：同步空间信息（纪元、是否加密、加密盐与校验值）
  - `e{epoch}/changes/{device}/{hlc}.bin`：各设备上传的增量（gzip 压缩，可加密）
  - `e{epoch}/snapshots/*.bin`：压缩合并后的全量快照（保留最近 3 份；被覆盖的增量 7 天后清理）
  - `e{epoch}/versions/*.bin`：手动上传的云端完整备份
- 增量文件超过阈值时自动压缩为快照；更换加密方式会开启新纪元，旧设备会自动重新拉取。
- 本地版本快照保留策略：手动快照永久保留；自动快照保留最近 7 天全部、12 周内每周一份、更早每月一份。

## 本地开发

```bash
npm install
npm run dev       # 开发服务器 http://localhost:5173
npm test          # 单元测试（时间计算、同步引擎、CSV、统计、版本保留）
npm run check     # 类型检查
npm run build     # 构建到 dist/（可用 BASE_PATH=/repo/ 指定部署路径）
npm run preview   # 预览构建结果
```

技术栈：Svelte 5 + TypeScript + Vite、vite-plugin-pwa（Workbox）、Dexie（IndexedDB）、aws4fetch（S3 V4 签名）、fflate（gzip）、Web Crypto、lucide 图标。

## 数据格式

- JSON 备份：`{ app: "lyubishchev-time", schemaVersion, exportedAt, deviceId, data: { categories, entries, todos, plans, reviews } }`，加密备份为 `{ format: "encrypted", ... }` 信封。
- CSV 导入支持的列：日期、开始/结束（日期时间）、开始时间/结束时间、时长（`90`、`1:30`、`1h20m`、`2小时15分`）、分类（可用 `父/子` 路径，自动创建）、类型、备注、标签、产出数量、单位。
